The first release of the Cloud Registry UI, a web app for browsing and
managing services in a [Cloud
Registry](https://cloud-registry.readthedocs.io/en/latest/), published as the
image `elixircloud/cloud-registry-ui:1.0.0-rc1` and tested against
cloud-registry 1.0.0rc1 (the registry spells its pre-releases the PEP 440
way, the app the SemVer way). It covers the registry's API for anyone, users
and admins, and takes the registry's registration rules from its service
info. See the [operator guide](../operator-guide/index.md) to deploy it, the
[upgrade notes](../operator-guide/upgrading.md#changes-since-unreleased-versions)
for the breaking changes below, which affect deployments of earlier,
unreleased versions, and the [user guide](../user-guide/index.md) to use it.

## Breaking changes

- Login providers are configured with `LOGIN_PROVIDERS` and
  `LOGIN_REDIRECT_URI`: the app no longer reads `LS_LOGIN_URL` and
  `OIDC_*`, and stops with a message (on Vercel, the build fails) if they
  are set without `LOGIN_PROVIDERS` (#49)
- The allowed environments and URL schemes of services come from the
  registry's service info: `NEXT_PUBLIC_SERVICE_ENVIRONMENTS` and
  `NEXT_PUBLIC_SERVICE_URL_SCHEMES` are ignored, with a warning when the app
  starts (#128, #144)
- All settings are read when the app starts, not when the image is built:
  pass them with `docker run`; `NEXT_PUBLIC_*` build arguments only print a
  warning (#86)

## Features

- Browse, search and filter services, with their details, verifications and
  pending entries (#27, #29, #30, #31, #41, #79)
- Register, edit, rename and delete services; admins can choose service IDs
  (#24, #53, #92)
- Manage access: grant and revoke roles of users and groups, and invite users
  to services by link (#43, #105, #114)
- Show the limit of services per user clearly (#115, #109, #116)
- Switch between user and admin mode (#93)
- Show and approve pending services and service types, and add and delete
  service types (#55, #57)
- Log in with one or several OpenID Connect providers (such as LS Login),
  configured at start (#49, #86)
- Read the allowed environments and URL schemes of services from the
  registry's service info, instead of the app's settings (#128, #144)
- Register services with the create form of cloud-components 2.0.0-alpha.50:
  service types picked from the registered ones, new types only where the
  registry accepts them (with a note when they need approval), environments
  from the registry, admin-only fields in admin mode only, and the
  registry's problem details in errors (#129, #145)
- Show the registry's registration rules on the service info page, offer
  adding service types only where the registry accepts new types, and
  explain conflicts of service types (#131, #147)
- Pick service types from the registered ones in the edit form, as in the
  form for new services; offer new types only to users who may add them
  (#130, #148)
- Check registrations in the create form before sending them, as the
  registry does (required fields, URLs and their schemes, environments,
  lengths), and offer new types there only where the registry accepts them
  (#35, #149)

## Security

- Login with PKCE and a nonce; the app checks the issuer, audience, expiry and
  party of ID tokens and the issuer name of responses (RFC 9207) (#49, #74,
  #88)
- Fresh credentials for every login (#96)
- Hardened image and security headers; settings and secrets are read at start
  and stay out of the image (#67, #78, #86)
- axios 1.21.0 and zod 4.6.7, which fix high-severity advisories in the
  calls to the login providers (credential headers on redirects, proxy
  bypasses, ReDoS) and in input validation (memory exhaustion) (#153, #159)
- Bun 1.4.4 image, with the Debian security updates that fix critical and
  high vulnerabilities of the 1.3.14 image (e.g., in Perl, OpenSSL and
  util-linux) (#154, #163)

## Fixes

- Keep the top bar in view next to wide tables (#108)
- Warn of old login settings (`LS_LOGIN_URL`, `OIDC_*`) that are still set
  next to `LOGIN_PROVIDERS`, and log each provider's issuer as discovered
  (#152, #158)
- Title the details of a service "Service Details", group their buttons
  into rows that fit, and wrap long values (names, URLs, the JSON), so that
  the dialog no longer scrolls sideways, also on phones (#165, #173)
